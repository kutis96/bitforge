# bitforge — Decisions (locked)

Requirements and design decisions agreed with the user. **Treat these as fixed** unless the user explicitly re-opens one. If a decision looks wrong, flag it — don't silently change it.

## Format & data
1. **No native/JSON project file.** PNG atlas is the working format; Verilog is export-only. — **Superseded by #64** (2026-11-15): the user re-opened this; the `.bitforge` project file exists, and PNG remains primary for finalized fonts.
2. Exactly **256 glyphs** per font, 8-bit codepoints (0–255), "ASCII-ish". No Unicode beyond 8-bit.
3. Atlas is always **16×16** characters.
4. Glyph size **W×H is parametric per font**, default **8×16**. Any positive integer, soft-capped ~1–64.
5. **Import** derives W = imgWidth÷16, H = imgHeight÷16; **throw an error if not a whole number.**
6. Pixel semantics: `1` = ink (black), `0` = transparent (white/background).

## Import (PNG)
7. Ink test: **composite pixel over white, luminance < 128 ⇒ ink.** (Covers black-on-white, transparent backgrounds, and light checkerboard cell borders.)

## Export
8. **PNG:** exactly `16W × 16H` (1px per bit). Ink = black. Background = **white or transparent** (user toggle).
9. **Verilog `$readmemb`:** binary, one line per row, `width` bits/line, **rightmost pixel = MSB** (visual row reversed), top→bottom, glyph 0 first, `256*height` lines, `1`=ink/`0`=transparent, **no headers/comments**.

## Rendering
10. **Artificial bold:** double-draw with a **1px** horizontal offset.
11. **Slant:** per-row horizontal offset. Baseline row = offset **0** (selectable, default **line 5 from the bottom**). Rows above the baseline → **non-negative** offset; rows below → **negative** offset. Slanted glyphs **spill into neighbours** (ink-only compositing). Exact per-row math is an implementation detail in a small module.
12. All rendering is **ink-only** (black) over a transparent/white background → overlaps compose correctly.

## UI / UX
13. **Black on white** (explicitly **not** green/amber). Monospace, terminal-tool aesthetic.
14. Layout: **left glyph-selector sidebar** + main tabs **[ Edit | Preview | Atlas ]**.
15. Editor **and** glyph preview both show the **hex code + printable char** (char shown for `0x20`–`0x7E`).
16. **Editing:** left-click toggles, left-drag paints, right-drag erases; undo/redo.
17. **Preview tab:** single-glyph zoom (scale + bold + slant + baseline) **and** multi-line text sample.
18. **Selector:** 16×16 mini-glyph grid + jump field (hex or literal char).
19. Preview **scale ≈ 1×–16×**.

## Preview markup
20. `*bold*`, `_italic_` (nestable for both), **`\uXX`** (2 hex digits) for unprintables. `*`/`_` toggle the attribute; a **literal** `*`/`_` is typed as `\u2A`/`\u5F`.
21. Typed char **> 255** → **red square** (glyph-sized).

## Tech
22. **Vanilla JS, single-page, no build, no dependencies, no ES modules** (must run from `file://`). Single self-contained `index.html`, or split into `css/` + `js/` (plain scripts) — either is fine.
23. **No Go backend, no Node/TS.** No server component.
24. PNG I/O via `<canvas>` (no PNG library).
25. **localStorage** auto-save as the only persistence (no project file). — **Superseded by #64**: localStorage is still the auto-save, but no longer the *only* persistence.
26. **Code split:** `js/core.js` = pure, DOM-free logic (global `BF`); `js/app.js` = DOM wiring (canvas, events, file ops). Keep pure logic in `core.js` so it stays testable.
27. **Unit tests run headlessly** under macOS JavaScriptCore (`jsc`) via `test/run-tests.sh`; no Node/browser. DOM code is verified in a browser.

## Editor guidelines
28. **Guidelines are editor-only.** Stored per-font in `Font.guidelines[]` (`{ o: "h"|"v", off, label, color }`, `off` in glyph-pixel units), persisted to `localStorage` with the font, **never exported** to PNG or Verilog.
29. **Shared per font**, not per glyph. Offsets clamp to `0..(dim-1)` (the line must stay on the canvas). Saved entries are sanitized on load (localStorage is user-editable).
30. **Hard to move/remove by accident:** a global **lock is ON by default** (dragging disabled; pixel editing unaffected). Guides are added via preset buttons (ascender / cap / x-height / baseline / descender / left / right / free H / free V), moved by dragging when unlocked (hover shows a resize cursor), and removed via the `×` on their chip in the live list.
31. Preset default offsets are computed from W/H (e.g. baseline = `H-3`, descender = `H-1`, x-height = `round(H*0.40)`); exact values/colors live in `GUIDE_PRESETS` in `js/app.js` and are tunable.

## Ergonomics (chunk I)
32. **Keyboard glyph navigation:** `←/→` ±1 · `↑/↓` ±16 (atlas row) · **`Home/End` = start/end of the current 16-cell atlas row** (not the whole atlas — user spec) · `PgUp/PgDn` = 0x00/0xFF. All suppressed while a text input has focus.
33. **Reference glyph:** Shift-click in the sidebar atlas sets it; Shift-click the same cell again clears it. Drawn as a **light-gray underlay** behind the active glyph in the editor (solid gray; diagonal hatching is an acceptable substitute). **Session-only** (not persisted). Editor tab only.
34. **Glyph shift is keyboard-only** (user: no button clutter for small ops): `Ctrl/⌘ + arrows` shift the current glyph's ink ±1px. Ink shifted out of bounds is **dropped**, with a toast if anything was lost. One undo step per shift.
35. **The shortcut registry is the only way to bind a shortcut.** `shortcuts.register({ combo, description, handler })` in `app.js`; one global dispatcher; the **reference card** (toggled with `?`, plus a toolbar button) is rendered *from* the registry so it cannot drift. Existing undo/redo migrate to it. No raw `keydown` listeners for app shortcuts — ever.
36. **Inverted preview toggle:** white-on-black on the preview surfaces (glyph zoom, text sample, atlas) — how the font will look in a real terminal. Editor and sidebar stay black-on-white.
37. **Atlas honors the current bold/slant state** (same state as Preview; no separate controls). Extra horizontal column spacing while slant is on, so spill stays legible.

## QA (chunk J)
38. **Glyph status:** 3 states per glyph — `unfinished` (0, default) / `wip` (1) / `done` (2). Stored in `Font.status`, persisted with the font, **never exported**. Absent in old saves ⇒ all unfinished.
39. **Status assignment & display:** in the Atlas tab, **left-click selects** a glyph, **right-click opens the 3-choice status menu** (left-click = select keeps navigation consistent with the sidebar). Tints: WIP = very light peach, unfinished = very light pastel blue, done = plain white; applied in the atlas and as a subtle tint in the sidebar selector.
40. **Settings API for small persistable UI values:** `settings.get(key)` / `settings.set(key, value)` over a declared defaults table (one JSON blob). First persisted: preview text, scale, bold, italic, baseline, inverted. **No raw `localStorage` for settings.** The font blob stays on its own path (large data, own sanitizing). New persistable value ⇒ defaults table + API.
41. **QA tab (4th tab):** violations table + **Refresh** button + **stale badge**. Staleness = monotonic font-version counter bumped on every font mutation (edit stroke end, clear, shift, status change, import, new font); a report stores the version it was computed at and is stale whenever they differ.
42. **First QA checks:** (a) **duplicate glyphs** — codepoints with identical bitmaps, grouped; the all-empty group is excluded as pre-drawing noise; (b) **what's left to draw** — status counts (256 and printable 0x20–0x7E) + clickable list of unfinished/WIP glyphs that selects/jumps to the glyph. **Checks are registered `(font) → rows` functions** so later checks plug in without touching the table.

## Interop (chunk K)
43. **BDF import/export:** import the **first face** of a standard BDF (`BW`→W, `DH`→H; malformed ⇒ error; extra faces ignored; status/guidelines start fresh on import). Export: one face, all 256 codes, standard fields, hex BITMAP rows, leftmost pixel = MSB. BDF may carry comments (text interchange format; the no-comments rule is Verilog-only).
44. **Copy glyph to clipboard:** current glyph rendered to PNG at **16× scale, transparent background**; `navigator.clipboard.write`, **falling back to a PNG download** where clipboard is unavailable (file:// caveats); toast the outcome.
45. **Explicitly out:** hex Verilog export (binary only, #9), ROM size readout, pre-baked bold ROM — bold/italic are handled by the terminal's display logic, not extra ROM (user).

## Edge-ink QA (chunk N.2)
60. **Edge-ink lint** (greenlit 2026-11-15; implements the long-deferred #46): `BF.edgeInk(font, code)` (core.js section [10]) returns the cell edges a glyph's ink touches — a subset of `top`/`bottom`/`left`/`right` (top = row 0, bottom = row H-1, left = col 0, right = col W-1); blank glyphs return `[]`. The QA check **edge-ink** (severity **warning**, **silenceable** per glyph) raises one row per offending glyph, detail "ink touches the … edge(s)". Rationale: at zero letter spacing, edge ink visually collides with the neighbour; box-drawing/pseudo-graphics that touch edges by design are silenced per glyph (the N.1 mechanism).

## Guideline-violation QA (chunk N.3)
61. **Guideline-violation report** (greenlit 2026-11-15; implements the long-deferred #47): **label-aware bounds** (user's pick over a min/max bounding box — a lone baseline guide must never collapse bounds to a line, and reference guides must never be bounds): only guides labelled `asc`/`desc`/`L`/`R` act as bounds; cap/x/base/free guides stay reference-only. `BF.GUIDE_BOUND_LABELS` (core.js) is the single source of the four bound labels — the app's `GUIDE_PRESETS` references it (saved fonts keep working; the label strings are unchanged). `BF.guideBounds(font)` → topmost ascender / lowest descender / leftmost L / rightmost R (outermost wins on duplicate labels). `BF.guideViolations(font, code)` → `[{ bound, label, over }]` (over = overshoot in px; ink exactly on a bound line is fine; blank glyphs / missing bounds ⇒ nothing). The QA check **guideline violations** (severity **warning**, **silenceable** per glyph) raises one row per glyph whose detail names the crossed guide by its chip label + overshoot: `ink 2px above the "asc" guide; 1px right of the "R" guide`. — **Refined by #65:** guides are drawn *between* pixels, so the precise contract is: top/left outside = ink at index `< off`; bottom/right outside = ink at index `>= off` (the "ink on the line is fine" phrasing assumed on-pixel lines).

## Preview newline fix (chunk O.2)
63. **Newlines render as line breaks; markup state spans lines** (user report, 2026-11-15): the old `drawPvText()` parsed each raw line *separately* and then packed the items into display rows by appending to the last row while it had space — a new display row was only started by `maxCols` overflow. Consequences: a single `\n` vanished entirely (its line's items merged into the previous row), `N` newlines rendered `N−1` breaks, blank lines were swallowed, and the per-line parsing reset `*bold*`/`_italic_` state at every line boundary. Fix: `BF.parseMarkup` now emits a break token `{ code: -1, ok: true, nl: true }` per `\n` (formatting state carried across; DOM-free, so core-tested), and `drawPvText()` parses the **whole text once** and lays it out: every `nl` item starts a new display row (blank lines render as blank rows; a trailing newline adds one), while `maxCols` still soft-wraps long rows. `*AAA⏎AAA*` now renders both lines bold.

## Project file (.bitforge) (chunk O.3)
64. **Project file** (user re-opened #1/#25, 2026-11-15): a **`.bitforge`** project file — plain JSON, WIP snapshot. **PNG remains the primary interchange format for finalized fonts**; the project file is what carries the things a PNG can't: editor guidelines, glyph status, QA silences, and the small settings. Format (version 1): `{ "app": "bitforge", "kind": "font-project", "version": 1, "font": {w,h,d,g,s,si}, "settings": {...} }` — `font` is the **exact localStorage blob shape**; `settings` holds settings-API keys, is **optional on import** (missing → keep current values; unknown keys dropped; per-key type rules identical to the settings loader). Forward compat: this build reads `version === 1` only; anything else is rejected with a named error. The blob shape + all sanitizing moved to core.js — `BF.fontToBlob(font)` / `BF.fontFromBlob(obj, knownCheckIds)` — and are shared by localStorage restore, export, and import (no second serializer). One deliberate relaxation: a blob missing `d` now restores as a blank font at the saved dimensions (previously it failed to a fresh 8×16). UI: File → **Open project…** (`Alt+P`) and **Export project…** (`Alt+Shift+P`, suggested name `font-WxH.bitforge`); import follows the PNG pattern (confirm → replace → toast). No font-name field in v1 (user agreed to defer).

## Bound-guide off-by-one (chunk O.4)
65. **Guidelines are drawn BETWEEN pixels; the bottom/right comparison was off by one** (user report ×2, 2026-11-15/16): guide lines render on grid boundaries — a guide at offset `off` sits **between** indices `off-1` and `off` (canvas coord `off*scale + 0.5`), never on a pixel. `BF.guideViolations` was written for on-pixel line semantics: bottom/right used `maxR > off` / `maxC > off` ("ink on the line is fine"), so the pixel at index `off` — the **first** pixel below/right of the line — was never flagged. E.g. with an R guide at 6 (line between cols 5|6), ink in col 6 — immediately right of the line — was NOT flagged, only col 7 was: visually one pixel off, exactly as the user reported. Top/left (`minR < off` / `minC < off`) were already correct — exactly why asc/L worked and desc/R didn't. **Fix:** bottom/right now use `maxR >= off` / `maxC >= off`, and overshoot counts pixel rows/cols outside the line (`maxR - off + 1`). Consequence: the **original** preset values (`descender` `h-1`, `right` `w-1`) are correct — each line leaves exactly 1px outside (row `h-1` / col `w-1`), same as asc/L. The first [O.4] attempt (presets → `h-2`/`w-2`) was a misdiagnosis of this same off-by-one and is reverted. Existing fonts' saved guide positions are unaffected by either change. Pinned by core tests covering all four directions (bottom+left added in the first attempt) and a DOM test on the preset positions (`guidePresets` seam export).

## PNG atlas to/from clipboard (chunk O.5)
66. **Clipboard PNG atlas export + import** (user request, 2026-11-16): File → **Copy PNG to clipboard** (`Alt+Shift+C`) rasterizes the whole atlas with the **remembered `pngBg`** background (same canvas as the file export — the builder is now shared as `atlasCanvas()`) and writes an `image/png` ClipboardItem, with the same fallback as the single-glyph copy: download the file when the clipboard API is unavailable or the write is blocked. The success path needs a real browser (image decode); headless tests cover write, download fallback, no-PNG-on-clipboard, and read-denied (the stub's clipboard gained a `read()` fed by `__stub.clipboardRead` / `__stub.clipboardReadError`). — **Closed 2026-11-16:** the user declined the Ctrl+V offer — no paste binding; a stray paste must not be able to replace the font unconfirmed.

## Move/copy paste modes (chunk U)
76. **Paste modes for dragged selections + copy-drag** (user greenlight, 2026-11-19): two orthogonal refinements to [T]'s move-by-drag, forming a 2×2 — {cut, copy} × {merge, replace}:

## TTF OTS compliance (chunk [Z.2])
85. **TTF export fixed for Windows/Chromium — OTS-compliant (chunk [Z.2], 0.27.2)** (user report, 2026-11-25 — "the TTF font export is currently broken, at least on Windows with Chromium — I get OTS parsing errors: bad table directory searchRange / rangeShift, Table directory is not correctly ordered, OS/2: Error reading more basic table fields / Failed to parse table"):
   - **Root cause class:** CoreText (our macOS oracle) is **lenient**; Chromium's **OTS** is strict. The CoreText-only verifier let all five bugs through — they only surface on Windows/Chromium. The five bugs, fixed in `js/ttf.js`:
     1. **Table directory** `searchRange = 16 × 2^⌊log2 n⌋`, `rangeShift = n×16 − searchRange` (records are 16 bytes wide). The old code used the *cmap* subtable's 2-byte formula (`×2`) for the directory — wrong for both fields.
     2. **Table directory order:** tables sorted by tag ascending before the directory is built (`"OS/2"` 0x4F sorts **before** `"cmap"` 0x63). OTS: "Table directory is not correctly ordered"; CoreText doesn't care.
     3. **OS/2 v4 (96 bytes)** rewritten in OTS's read order — the subscript/superscript/strikeout/familyClass fields sit **after `fsType`** for *every* version, so the table must be ≥ 78 bytes (v0 at 56 fails OTS regardless of declared version). `usDefaultChar`/`usBreakChar` = 0x20 (space).
     4. **cmap format-4 terminator:** the final segment's start **and** end must be `0xFFFF` (OTS: "Final segment start and end must be 0xFFFF"). Terminator `[0xFFFF,0xFFFF]`, idDelta 1 → glyph 0 (.notdef); codes 0x100..0xFFFE sit in *no* segment ⇒ unmapped ⇒ per-codepoint fallback (the dogfooding safety rule is preserved).
     5. **`fsSelection` = 0x40** (bit 6 REGULAR). Bit **0 is ITALIC**, not REGULAR — setting bit 0 made OTS warn "Adjusting head.macStyle (italic)".
   - **The one failing test was a TEST bug, not a builder bug:** `test-ttf.js`'s final-segment assertion read the *last startCode* at `base+16+2(n−1)` = the **reservedPad** slot (always 0). The real last startCode is at `base+16+4n−2` (startCode array begins after `endCode[n]` + reservedPad: `base+14+2n+2`). Fixed the offset; `js/ttf.js` was already correct. (The handoff had misdiagnosed it as an off-by-one in `buildCmap`'s write loop — it wasn't.)
   - **Oracle stack (no system-wide installs):** a real OTS build reproduces the user's exact errors and now reports clean. venv `/tmp/bfvenv` (pip `meson`+`ninja`+fontTools); sources `/tmp/ots-src`; build `/tmp/ots-build`. **Run `/tmp/ots-build/ots-sanitize <font.ttf>`** → exit 0 + "File sanitized successfully!" = Chromium-clean. Rebuild-if-wiped: `PATH=/tmp/bfvenv/bin:$PATH meson setup /tmp/ots-build /tmp/ots-src && meson compile -C /tmp/ots-build`. OTS findings are **cumulative** — iterate until zero warnings. `tools/verify-ttf.py` also gained a hard `check_sfnt_structure()` (directory formula, tag order, 4-align, overlap, OS/2 min-lengths 78/86/96, fsSelection↔macStyle italic, cmap terminator) that runs in **both** modes before the CoreText load. Cross-check that our cmap is readable by a real library: `/tmp/bfvenv/bin/python3 -c "from fontTools.ttLib import TTFont; ..."` on an exported file.
   - **Lesson (regression-tested):** for any binary format we emit, a *lenient* reader (CoreText) is not an acceptance oracle — validate against the *strictest* consumer we target (Chromium/OTS). Keep the CoreText verifier **and** add the OTS sanitizer to the touch-`js/ttf.js` ritual (see AGENTS.md).
